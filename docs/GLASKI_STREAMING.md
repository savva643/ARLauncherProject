# GlaskiOS: конвейер iPhone → LensEngine → Vulkan

Что сделано и как это проверить.

## Схема

```
iPhone (ARStreamer, ветка noarkit)
  камера 1920x1440@60, фокус зафиксирован, стабилизация выключена, выдержка ≤ 1/240 с
  интринсики и PTS у каждого кадра → аппаратный H.264/HEVC (low-latency, без B-кадров)
  сырой гироскоп и акселерометр 100 Гц, магнитометр 50 Гц, аппаратные таймстемпы
  LiDAR float16 + интринсики (по желанию)
        │  один TCP, протокол v2 (docs/PROTOCOL_V2.md); USB-модем → :9001, Wi-Fi → :9000
        ▼
SensorStream (ПК, без Qt)
  сетевой поток: разбор пакетов, IMU сразу в трекинг, синхронизация часов
  поток декодера: FFmpeg (VAAPI/CUDA или CPU) → NV12; публикуется только последний кадр
        ▼
LensEngine::TrackingSession  (аналог ARSession)
  HeadTracker: ориентация по сырому IMU (Mahony + оценка bias гироскопа), история, предсказание
  VioTracker: OpenVINS (MSCKF, моно-камера + IMU) → 6DoF, онлайн-калибровка камера↔IMU и сдвига времени
  без VIO: 3DoF + модель шеи (параллакс при поворотах головы)
        ▼
ARLauncher (Vulkan)
  2 кадра в полёте, MAILBOX (самый свежий кадр без очереди)
  LATE LATCHING: после acquire образа swapchain поза предсказывается на момент показа
  NV12 → GPU через staging (без конвертации на CPU), YUV→RGB в шейдере
  РЕПРОЕКЦИЯ: видео поворачивается из позы съёмки в позу показа — мир неподвижен
  несмотря на задержку видео 40–80 мс и на то, что дисплей быстрее камеры (120 Гц при 60 к/с)
  моно-окно или стерео side-by-side (ARL_STEREO=1)
```

## Почему не укачивает

Плавность для глаза определяют не FPS камеры и не разрешение, а:

1. **Задержка поворота головы до фотона.** Ориентация берётся из гироскопа в момент записи кадра (late latching) и экстраполируется на момент показа. Видео не нужно ждать.
2. **Нет «плавающего» мира.** Старое сглаживание `slerp(dt*15)` (экспоненциальный лаг около 66 мс) убрано. Вместо него предсказание.
3. **Репроекция видео.** Каждый кадр камеры показывается с учётом того, куда голова повернулась с момента экспозиции. Поэтому камера на 60 Гц выглядит на дисплее 120 Гц ровно.
4. **Частота дисплея.** Рендер идёт без ограничения, MAILBOX показывает самый свежий кадр. `ARL_FULLSCREEN=1` выбирает максимальную частоту монитора.

## Сборка и запуск

```bash
# ПК (Ubuntu 22.04/24.04)
./build_arlauncher.sh            # 3DoF + модель шеи
./build_arlauncher.sh --vio      # + OpenVINS (6DoF), один раз собирает third_party/openvins

cd ARLauncher/build_vk
./bin/ARLauncher
```

На iPhone: ARStreamer, ветка `noarkit` (собирается через Codemagic или Xcode).
Ориентацию телефона можно менять как угодно: поток на ПК всегда в родной ориентации сенсора, поворачивается только превью.
Настройки: **USB**, H.264, 1440p 4:3, 60 FPS, 30 Мбит/с.
Затем включите «Режим модема» по кабелю и нажмите «Подключиться».

### Переменные окружения

| Переменная | Значение |
|---|---|
| `ARL_FULLSCREEN=1` | полный экран, режим с максимальной частотой |
| `ARL_MONITOR=1` | номер монитора (дисплей шлема) |
| `ARL_STEREO=1` | стерео side-by-side |
| `ARL_IPD_MM=63` | межзрачковое расстояние |
| `ARL_FOV=90` | горизонтальный FOV глаза под линзы; по умолчанию как у камеры минус 10 % запаса |
| `ARL_PRESENT_MODE=mailbox\|fifo\|immediate` | режим показа (по умолчанию mailbox) |
| `ARL_PREDICT_MS=12` | фиксированное время предсказания; по умолчанию авто от частоты |
| `ARL_HWDEC=auto\|vaapi\|cuda\|none` | декодер видео |
| `ARL_MOUNT=auto\|0\|90\|180\|270` | крепление телефона: 0 — ландшафт, верх слева; 180 — верх справа; 90/270 — портрет. По умолчанию авто по гравитации (перевернули телефон — переключится само через ~1–2 с) |
| `ARL_LIDAR_TRACKING=0` | выключить позицию по LiDAR (тогда VIO или 3DoF + модель шеи) |
| `ARL_OCCLUSION=0` / `ARL_SHADOWS=0` / `ARL_LIGHTING=0` | выключить окклюзию / тени / свет и отражения комнаты |
| `ARL_AUDIO=0`, `ARL_HRTF=0` | выключить звук / HRTF |
| `ARL_MARKERS=0`, `ARL_MARKER_SIZE_CM=10` | метки ArUco и их размер |
| `ARL_HANDS=0` | выключить руки (модели — `models/`, путь можно задать `ARL_MODELS`) |
| `ARL_SHOW_ROOM=1` | сразу показывать меш комнаты и плоскости (то же, что V) |
| `ARL_WORLD_MAP=путь` / `ARL_WORLD_MAP=0` | файл карты комнаты (по умолчанию `~/.local/share/glaski/world.map`) / не сохранять |
| `ARL_LENS=1`, `ARL_LENS_K1/K2/CA/SCALE/SHIFT` | коррекция линз шлема и её параметры |
| `ARL_MIC_MONITOR=1` | микрофон сразу в наушники (то же, что F7) |
| `ARL_LIDAR_OVERLAY=1` | включить наложение LiDAR сразу (то же, что L) |
| `ARL_NO_VIO=1` | отключить OpenVINS |
| `ARL_GPU=<n>` | выбрать видеокарту |
| `ARL_VK_VALIDATION=1` | слой валидации Vulkan (отладка) |

### Клавиши

| Клавиша | Действие |
|---|---|
| **R** | recenter: «вперёд» = куда сейчас смотришь |
| **P** | вкл/выкл репроекцию — сравнить плавность |
| **O** | вкл/выкл предсказание |
| **M** | крепление телефона: авто → 0° → 90° → 180° → 270° → авто |
| **K** | окклюзия: реальные предметы закрывают виртуальные |
| **H** | тени на полу |
| **E** | свет и отражения комнаты |
| **U** | звук вкл/выкл |
| **V** | меш комнаты (пол, стены, стол, потолок цветом) и плоскости |
| **F5** | сохранить карту комнаты (при выходе сохраняется сама, плюс раз в минуту) |
| **G** | калибровка взгляда (9 точек; нужны камеры глаз) |
| **F6** | запись микрофона в `~/glaski_recordings/*.wav` (ещё раз — стоп) |
| **F7** | микрофон в наушники |
| **щипок** | большой + указательный: взять объект под взглядом/лучом руки, перенести, отпустить — он запомнится в комнате |
| **L** | наложение LiDAR цветом поверх видео (красный — близко, синий — далеко); проверка, что глубина приходит и совпадает с картинкой |
| **ESC** | выход |

Панель в углу окна показывает камеру/декодер, режим трекинга и позицию, частоту IMU и крепление, битрейт и LiDAR.
Лаунчер раз в 2 с печатает в консоль: FPS рендера, режим трекинга, возраст видео,
FPS и битрейт потока, частоту IMU, декодер.

## GlaskiOS Control (окно сборки и запуска)

```bash
sudo apt install python3-tk libopenal-dev   # окно и пространственный звук
python3 tools/glaski_control.py
```

Все переключатели выше — галочками; кнопки «Собрать и запустить», «Симулятор iPhone», «Собрать OpenVINS», журнал.
Настройки сохраняются в `~/.config/glaski/control.json`. Без окна: `python3 tools/glaski_control.py --run`.

## Тест без iPhone

```bash
cd ARLauncher/build_vk
./bin/ARLauncher &
./SensorStream/stream_simulator 127.0.0.1 9001 --seconds 60 --latency-ms 45 --depth   # --depth: LiDAR, проверка клавишей L
```

Симулятор крутит «голову» по известной траектории и шлёт сырой IMU с bias и шумом.
Видео — виртуальная камера внутри сферы-сетки (красный горизонт), с искусственной задержкой.
С репроекцией сетка стоит на месте; нажмите **P**, чтобы увидеть, как без неё мир «плывёт».

`--room` — комната 5×6 м с перегородкой, столом, шкафом и меткой ArUco (id 3, 30 см → `ARL_MARKER_SIZE_CM=30`);
«голова» ходит по комнате, LiDAR согласован с видео. Видно позицию по LiDAR (HUD), окклюзию (объекты за
перегородкой спрятаны), шар на полу с тенью и отражением комнаты, кубик на метке:

```bash
ARL_MARKER_SIZE_CM=30 ./bin/ARLauncher &
./SensorStream/stream_simulator 127.0.0.1 9001 --room --depth --fps 30 --size 960x720
```

`--eyes` — синтетические ИК-кадры глаз (модуль айтрекинга), `--audio` — микрофон.

Модели рук: `models/palm_detection_mediapipe_2023feb.onnx`, `models/handpose_estimation_mediapipe_2023feb.onnx`.
Для OpenCV 4.5/4.6 (Ubuntu 22.04/24.04) рядом лежит `*_compat.onnx` (сделан `tools/onnx_clip_compat.py`) —
подхватывается сам.

Проверка только приёма: `./SensorStream/stream_probe --seconds 10 --dump frame.pgm`.

Модульные тесты LensEngine (папка сборки LensEngineSDK):

```bash
./bin/test_head_tracker        # ошибка ориентации, оценка bias, предсказание +30 мс
./bin/test_tracking_session    # оси устройство/камера/глаз/мир в репроекции
```

## Цели по комфорту и что их ограничивает

| | Сейчас | Цель |
|---|---|---|
| Частота рендера | частота дисплея (MAILBOX) | 90–120 Гц |
| Поворот головы → фотон | ≈ 1 кадр дисплея + 3 мс, остаток компенсирует предсказание | < 20 мс (AVP ≈ 12 мс) |
| Видео камеры | 60 к/с, репроекция до частоты дисплея | — |
| IMU | 100 Гц (предел CoreMotion) | 500–1000 Гц (свой IMU в шлеме) |

Ограничения железа:

- **Одна камера** даёт моно-passthrough: обоим глазам одна картинка «на бесконечности». Для настоящего стерео нужны 2 камеры на IPD, либо синтез второго вида по LiDAR.
- **Нет коррекции дисторсии линз шлема.** Нужны параметры конкретных линз; финальный проход добавляется в Vulkan.
- **VIO (OpenVINS)** инициализируется так: 1–2 с держите голову неподвижно, потом начинайте двигаться. Лицензия OpenVINS — GPL-3.0.
