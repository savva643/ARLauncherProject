# Протокол потока iPhone → ПК, версия 2

Используется приложением **ARStreamer** (ветка `noarkit`) и библиотекой **SensorStream** в лаунчере.
Код: `ARStreamer/StreamProtocol.swift` ↔ `SensorStream/include/SensorStream/Protocol.h`.

## Транспорт

Один TCP-поток, `TCP_NODELAY`:

| Режим | Кто подключается | Порт ПК |
|---|---|---|
| USB (режим модема iPhone) | iPhone → ПК | 9001 |
| Wi-Fi | iPhone → ПК | 9000 |

ПК слушает `0.0.0.0` на обоих портах, поэтому USB-интерфейс (`172.20.10.x`) подхватывается автоматически.
UDP убран: keyframe H.264 больше 64 КБ и не помещается в датаграмму.

## Пакет

```
[type u8][sequence u64 big-endian][payloadSize u32 big-endian][payload]
```

Заголовок такой же, как в старом протоколе. Все поля внутри payload — **little-endian**.

**Время.** Наносекунды аппаратных часов iPhone (host clock / `mach_absolute_time`). На этих же часах
живут PTS кадра камеры, `CMLogItem.timestamp` у CoreMotion и время LiDAR. Поэтому IMU и камера
синхронизированы точно, без привязки к моменту отправки.

## Типы пакетов

### 0x20 HELLO — начало сессии (16 байт)

| off | тип | поле |
|---|---|---|
| 0 | char[4] | `"GLSK"` |
| 4 | u16 | версия протокола = 2 |
| 6 | u16 | резерв |
| 8 | i64 | текущее время телефона, нс |

ПК сбрасывает декодер и синхронизацию часов.

### 0x21 VIDEO — кадр видео (48 байт заголовка + данные)

| off | тип | поле |
|---|---|---|
| 0 | u8 | кодек: 1 = H.264, 2 = HEVC, 3 = JPEG |
| 1 | u8 | флаги: бит 0 = keyframe |
| 2 | u16 | резерв |
| 4 | u16 | ширина |
| 6 | u16 | высота |
| 8 | i64 | PTS — начало экспозиции, нс (часы телефона) |
| 16 | f32 ×4 | fx, fy, cx, cy — интринсики **этого** кадра в пикселях |
| 32 | u32 | выдержка, мкс |
| 36 | u32 | резерв |
| 40 | i64 | время отправки, нс (часы телефона) |
| 48 | … | Annex-B (start codes); на keyframe перед кадром идут VPS/SPS/PPS |

### 0x22 IMU — пачка сырых сэмплов (16 + 24·N байт)

Заголовок:

| off | тип | поле |
|---|---|---|
| 0 | u16 | N — число записей |
| 2 | u16 | резерв |
| 4 | u32 | резерв |
| 8 | i64 | время отправки, нс — по нему ПК синхронизирует часы |

Запись (24 байта):

| off | тип | поле |
|---|---|---|
| 0 | i64 | время сэмпла, нс |
| 8 | u8 | вид: 0 = гироскоп (rad/s), 1 = акселерометр (m/s², specific force), 2 = магнитометр (µT) |
| 9 | u8×3 | резерв |
| 12 | f32×3 | x, y, z в осях устройства CoreMotion |

Особенности данных:

- **Сырые данные без фьюжна Apple.** `startGyroUpdates`, `startAccelerometerUpdates`, `startMagnetometerUpdates`. Bias гироскопа не вычтен.
- **Знак акселерометра:** стандарт IMU. В покое экраном вверх z = +9.81. CoreMotion отдаёт `-a` в g, на телефоне знак переворачивается и значение умножается на 9.80665.
- **Частоты:** гироскоп и акселерометр 100 Гц (это максимум CoreMotion), магнитометр 50 Гц. Пачка уходит на каждом сэмпле гироскопа.

### 0x23 DEPTH — карта глубины LiDAR (32 байта заголовка + данные)

| off | тип | поле |
|---|---|---|
| 0 | i64 | время, нс |
| 8 | u16 | ширина |
| 10 | u16 | высота |
| 12 | u8 | формат: 0 = float16 метры, 1 = float32 метры |
| 13 | u8 | confidence: 0 = нет |
| 14 | u16 | резерв |
| 16 | f32 ×4 | fx, fy, cx, cy — в пикселях карты глубины |
| 32 | … | глубина, плотно упакована |

### Legacy-пакеты

ПК их по-прежнему понимает, чтобы старое приложение тоже работало:

- `0x01` — JPEG без метаданных
- `0x03` — 128 байт fused CMDeviceMotion
- `0x0A` — ориентация, double градусы. Шлётся и сейчас, но ПК крепление определяет по гравитации.

## Синхронизация часов

ПК оценивает смещение `pcRecv − phoneSend` по нижней огибающей за скользящее окно 4 с.
Берутся маленькие IMU-пакеты и HELLO. По USB погрешность — доли миллисекунды.
Так ПК знает, в какой момент по часам телефона кадр будет показан на дисплее.
