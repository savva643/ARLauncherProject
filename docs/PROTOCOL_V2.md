# Протокол потока iPhone → ПК, версия 2

Обратное направление (готовая картинка ПК → экран телефона) описано в разделе «Возврат картинки».

Используется приложением **ARStreamer** (ветка `noarkit`, версия без ARKit) и библиотекой **SensorStream** в лаунчере.
Код: `ARStreamer/StreamProtocol.swift` ↔ `SensorStream/include/SensorStream/Protocol.h`.

## Транспорт

Один TCP-поток, `TCP_NODELAY`:

| Режим | Кто подключается | Порт ПК |
|---|---|---|
| USB (режим модема iPhone) | iPhone → ПК | 9001 |
| Wi-Fi | iPhone → ПК | 9000 |

ПК слушает `0.0.0.0` на обоих портах, поэтому USB-интерфейс (`172.20.10.x`) подхватывается автоматически.
UDP убран: keyframe H.264 больше 64 КБ и не помещается в датаграмму.

## Пакет

```
[type u8][sequence u64 big-endian][payloadSize u32 big-endian][payload]
```

Заголовок такой же, как в старом протоколе. Все поля внутри payload — **little-endian**.

**Время.** Наносекунды аппаратных часов iPhone (host clock / `mach_absolute_time`). На этих же часах
живут PTS кадра камеры, `CMLogItem.timestamp` у CoreMotion и время LiDAR. Поэтому IMU и камера
синхронизированы точно, без привязки к моменту отправки.

## Типы пакетов

### 0x20 HELLO — начало сессии (16 байт)

| off | тип | поле |
|---|---|---|
| 0 | char[4] | `"GLSK"` |
| 4 | u16 | версия протокола = 2 |
| 6 | u16 | резерв |
| 8 | i64 | текущее время телефона, нс |

ПК сбрасывает декодер и синхронизацию часов.

### 0x21 VIDEO — кадр видео (48 байт заголовка + данные)

| off | тип | поле |
|---|---|---|
| 0 | u8 | кодек: 1 = H.264, 2 = HEVC, 3 = JPEG |
| 1 | u8 | флаги: бит 0 = keyframe, бит 1 = цвет указан (биты 2–3 валидны), бит 2 = full range, бит 3 = BT.709 (иначе BT.601) |
| 2 | u16 | резерв |
| 4 | u16 | ширина |
| 6 | u16 | высота |
| 8 | i64 | PTS — начало экспозиции, нс (часы телефона) |
| 16 | f32 ×4 | fx, fy, cx, cy — интринсики **этого** кадра в пикселях |
| 32 | u32 | выдержка, мкс |
| 36 | u32 | резерв |
| 40 | i64 | время отправки, нс (часы телефона) |
| 48 | … | Annex-B (start codes); на keyframe перед кадром идут VPS/SPS/PPS |

**Ориентация.** Кадр всегда в родной ориентации сенсора (ландшафт, `videoRotationAngle = 0`), без зеркала.
Поворот телефона и интерфейса поток не меняет: поворачивается только превью на экране iPhone.
Карта глубины LiDAR — в той же ориентации и выровнена с кадром. Крепление в шлеме ПК определяет по гравитации.

**Цвет.** Если бит 1 установлен, ПК берёт диапазон и матрицу из флагов, а не из VUI потока.
iPhone пишет 420f (full range) и BT.709. JPEG-режим всегда отдаёт full range + BT.601.

### 0x22 IMU — пачка сырых сэмплов (16 + 24·N байт)

Заголовок:

| off | тип | поле |
|---|---|---|
| 0 | u16 | N — число записей |
| 2 | u16 | резерв |
| 4 | u32 | резерв |
| 8 | i64 | время отправки, нс — по нему ПК синхронизирует часы |

Запись (24 байта):

| off | тип | поле |
|---|---|---|
| 0 | i64 | время сэмпла, нс |
| 8 | u8 | вид: 0 = гироскоп (rad/s), 1 = акселерометр (m/s², specific force), 2 = магнитометр (µT) |
| 9 | u8×3 | резерв |
| 12 | f32×3 | x, y, z в осях устройства CoreMotion |

Особенности данных:

- **Сырые данные без фьюжна Apple.** `startGyroUpdates`, `startAccelerometerUpdates`, `startMagnetometerUpdates`. Bias гироскопа не вычтен.
- **Знак акселерометра:** стандарт IMU. В покое экраном вверх z = +9.81. CoreMotion отдаёт `-a` в g, на телефоне знак переворачивается и значение умножается на 9.80665.
- **Частоты:** гироскоп и акселерометр 100 Гц (это максимум CoreMotion), магнитометр 50 Гц. Пачка уходит на каждом сэмпле гироскопа.

### 0x23 DEPTH — карта глубины LiDAR (32 байта заголовка + данные)

| off | тип | поле |
|---|---|---|
| 0 | i64 | время, нс |
| 8 | u16 | ширина |
| 10 | u16 | высота |
| 12 | u8 | формат: 0 = float16 метры, 1 = float32 метры |
| 13 | u8 | confidence: 0 = нет |
| 14 | u16 | резерв |
| 16 | f32 ×4 | fx, fy, cx, cy — в пикселях карты глубины |
| 32 | … | глубина, плотно упакована |

### 0x24 AUDIO — микрофон (16 байт заголовка + сэмплы)

Шлёт ARStreamer (настройка «Микрофон → ПК») или модуль микрофона шлема.

| off | тип | поле |
|---|---|---|
| 0 | i64 | время первого сэмпла, нс (часы источника) |
| 8 | u32 | частота дискретизации (ARStreamer: 16000) |
| 12 | u8 | число каналов (чередуются) |
| 13 | u8 | формат: 1 = PCM16 little-endian |
| 14 | u16 | резерв |
| 16 | … | сэмплы |

ARStreamer шлёт пачки по 20 мс (320 сэмплов). Лаунчер: уровень в панели, F6 — запись в WAV, F7 — слушать в наушниках.

### 0x25 EYE — кадр ИК-камеры глаза (16 байт заголовка + пиксели)

Для модуля айтрекинга шлема (в iPhone таких камер нет). Кадры обоих глаз идут отдельными пакетами.

| off | тип | поле |
|---|---|---|
| 0 | i64 | время экспозиции, нс |
| 8 | u8 | глаз: 0 = левый, 1 = правый |
| 9 | u8 | формат: 1 = GRAY8 |
| 10 | u16 | ширина |
| 12 | u16 | высота |
| 14 | u16 | резерв |
| 16 | … | пиксели (ширина × высота) |

Рекомендуется 60–120 Гц, 160×120…400×300, ИК-подсветка 850 нм (зрачок — тёмное пятно).
Лаунчер ищет зрачок (EyeTracker), калибровка по 9 точкам — клавиша G.

### Возврат картинки: ПК → телефон

Тем же TCP-соединением ПК отправляет на телефон готовую картинку лаунчера, телефон её показывает.
Режимы:

- **моно** — весь экран, как «окно» в AR;
- **стерео** — два глаза рядом;
- **стерео + линзы** — для VR-очков: искажение линз считает телефон.

Флаг «своя камера»: ПК рисует только объекты с альфой, а фоном служит живая камера телефона.

**Доворот (timewarp).** В каждом кадре ПК передаёт `predFromRef` — поворот устройства от последнего сэмпла
IMU (`tRef`) до момента, на который предсказана поза (`tTarget`). Перед показом телефон считает
свой поворот `A = R(tRef)⁻¹·R(t_показа)` по своему гироскопу. Затем строит луч:
`луч_глаза = eyeFromDevice · predFromRef⁻¹ · A · deviceFromScreen · луч_экрана`.

Повороты относительные, поэтому системы координат ПК и телефона согласовывать не нужно.
Эталон расчёта — `ReturnClient` в `stream_simulator.cpp`, на iPhone — `ARStreamer/ReturnDisplay.metal`.

#### 0x26 DISPLAY — телефон → ПК (40 байт)

| off | тип | поле |
|---|---|---|
| 0 | u8 | режим: 0 выкл, 1 моно, 2 стерео, 3 стерео + линзы |
| 1 | u8 | флаги: бит 0 — своя камера (ПК шлёт объекты + альфу), бит 1 — HEVC |
| 2 | u16 | ширина кадра (ландшафт, оба глаза) |
| 4 | u16 | высота |
| 6 | u16 | кадров/с |
| 8 | u32 | битрейт, кбит/с |
| 12 | f32 ×2 | tanX, tanY — полуугол глаза; 0 — ПК берёт FOV камеры |
| 20 | f32 | IPD, м |
| 24 | f32 | частота экрана, Гц |
| 28 | u32 | резерв |
| 32 | i64 | время телефона, нс |

ПК меняет размер окна под кадр, выключает свою коррекцию линз и HUD и включает чтение кадра с GPU.
Режим 0 — всё возвращается обратно. Обрыв соединения тоже выключает режим.

#### 0x30 RETURN_VIDEO — ПК → телефон (128 байт заголовка + Annex-B)

| off | тип | поле |
|---|---|---|
| 0 | u8 | кодек: 1 H.264, 2 HEVC |
| 1 | u8 | флаги: бит 0 keyframe, бит 1 альфа (кадр вдвое выше, снизу — альфа в яркости), бит 2 full range, бит 3 BT.709 |
| 2 | u8 | раскладка: 1 моно, 2 SBS |
| 3 | u8 | режим |
| 4 | u16 ×2 | ширина, высота закодированного кадра |
| 8 | u32 | frameId |
| 16 | i64 | tRef — последний сэмпл IMU, от которого предсказана поза |
| 24 | i64 | tTarget — момент, на который предсказана поза |
| 32 | i64 | tCamera — PTS кадра камеры в фоне (0 — фон с телефона) |
| 40 | i64 | время отправки (часы телефона) |
| 48 | f32 ×4 | predFromRef (x, y, z, w), оси устройства |
| 64 | f32 ×4 | eyeFromDevice |
| 80 | f32 ×4 | cameraFromDevice (камера OpenCV) |
| 96 | f32 ×3 | bias гироскопа (рад/с) по оценке ПК |
| 108 | f32 | overscan — кадр шире показа во столько раз (запас под доворот) |
| 112 | f32 ×2 | tanX, tanY отрендеренного глаза |
| 120 | f32 | IPD, м |

Цвет premultiplied, фон прозрачный (если есть альфа). На каждом keyframe перед кадром идут SPS/PPS.

#### 0x27 ACK — телефон → ПК (32 байта)

| off | тип | поле |
|---|---|---|
| 0 | u32 | frameId (0 — только запрос keyframe) |
| 4 | u8 | бит 0 — нужен keyframe |
| 8 | i64 | время приёма |
| 16 | i64 | время показа (presentedTime дисплея) |
| 24 | u32 | декодирование, мкс |

По ACK ПК меряет задержку «поза → фотоны» и предсказывает позу ровно на момент показа на телефоне.
Обычно расхождение получается около 0 мс.

### Legacy-пакеты

ПК их по-прежнему понимает, чтобы старое приложение тоже работало:

- `0x01` — JPEG без метаданных
- `0x03` — 128 байт fused CMDeviceMotion
- `0x0A` — ориентация, double градусы. Шлётся и сейчас, но ПК крепление определяет по гравитации.

## Синхронизация часов

ПК оценивает смещение `pcRecv − phoneSend` по нижней огибающей за скользящее окно 4 с.
Берутся маленькие IMU-пакеты и HELLO. По USB погрешность — доли миллисекунды.
Так ПК знает, в какой момент по часам телефона кадр будет показан на дисплее.
